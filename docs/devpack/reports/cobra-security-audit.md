# تقرير تدقيق أمني — Cobra (Dev Pack)

- **المشروع:** ساحة الفعاليات (Events-Square)
- **البيئة:** Laravel 13.8 + Inertia 3 + Sanctum 4 + spatie/laravel-permission 8 — PHP ^8.3
- **نطاق التدقيق:** الوسيط AdminMiddleware، المسارات، المصادقة، نموذج التواصل، رفع الملفات، وحدات التحكم الإدارية، الإعدادات، الترحيلات، النماذج
- **تاريخ التدقيق:** 2026-08-18
- **طبيعة المهمة:** بحث وتدقيق فقط — لم يُعدَّل أي ملف برمجي

---

## 1) نمذجة التهديدات (مختصرة)

### الأصول (Assets)
| الأصل | الوصف |
|---|---|
| A1 حساب المدير | admin@eventssquare-sa.com — تحكم كامل بالمحتوى والمستخدمين |
| A2 بيانات شخصية | جدول users (اسم/بريد/هاتف) وجدول contacts (اسم/بريد/هاتف/رسالة) — خاضعة لـ PDPL |
| A3 خادم الويب | مجلد public/uploads قابل للكتابة من الرفع |
| A4 المحتوى | الوجهات/الفعاليات/العروض/التقييمات/الإعدادات |
| A5 مفاتيح التشفير | APP_KEY وملف .env |

### الفاعلون (Actors)
| الفاعل | الدافع |
|---|---|
| مجهول خارجي | تخمين كلمة مرور المدير، سبام نموذج التواصل، استغلال ملف مرفوع |
| محرر (editor) داخلي | تصعيد صلاحيات إلى admin، تعطيل المدير، تسريب بيانات المستخدمين |
| مستخدم عادي | لا مسارات موجهة له حالياً (لا يوجد تسجيل/حساب مستخدم فعلي) |

### سطح الهجوم (Attack Surface)
1. `POST /login` — بلا حدّ لمحاولات الدخول.
2. `POST /contact` — بلا rate limiting أو captcha.
3. `POST/PUT /admin/testimonials` (و offers/events/listings) — رفع ملفات إلى `public/uploads`.
4. `POST /admin/users/{user}` و `DELETE /admin/users/{user}` — متاحة لـ editor.
5. `PUT /admin/settings` — متاحة لـ editor.
6. `GET /api/v1/user` — محمي بـ Sanctum (مقبول).
7. ملف `.env` — يُشحن مع قيم إنتاج خطرة إن نُشر كما هو.

## 2) الثغرات

> الخطورة: Critical / High / Medium / Low

---

### 🔴 C-01 — رفع ملفات تعسفي بلا أي تحقق → تنفيذ أوامر عن بُعد (RCE)

- **الخطورة:** Critical
- **الفئة:** File Upload / RCE
- **الملف:السطر:** `app/Http/Controllers/Admin/TestimonialController.php:32,47` + `app/Http/Controllers/Traits/UploadsFiles.php:12` + `config/filesystems.php:50-57`

**الوصف:**
حقل `avatar` في إضافة/تعديل التقييمات لا يمر بأي قاعدة تحقق (لا نوع، لا حجم، لا امتداد)، ثم يُخزَّن مباشرة عبر `uploadFile()` في القرص `uploads` الذي جذره **`public_path('uploads')`** — أي داخل الويب روت العلني. دالة `store()` تحافظ على امتداد الملف الأصلي في الاسم المُجزّأ.

**إثبات المفهوم:**
```http
POST /admin/testimonials
Content-Type: multipart/form-data; boundary=X

--X
Content-Disposition: form-data; name="author"

مهاجم
--X
Content-Disposition: form-data; name="content"

اختبار
--X
Content-Disposition: form-data; name="avatar"; filename="shell.php"
Content-Type: application/octet-stream

<?php system($_GET['c']); ?>
--X--
```
الرد سيحوي المسار المخزَّن، ثم: `GET /uploads/avatars/<hash>.php?c=whoami` → تنفيذ أوامر على الخادم (مؤكد على Apache/mod_php و nginx إذا كان `location ~ \.php$` يغطي المسار). حتى دون تنفيذ PHP، يسمح باستضافة برمجيات خبيثة/تصيّد تحت نطاق الموقع.

**الإصلاح:**
1. إضافة `'avatar' => ['nullable', 'image', 'mimes:jpg,jpeg,png,webp', 'max:2048']` للتحقق.
2. في `UploadsFiles`: رفض أي امتداد غير صوري (قائمة بيضاء `mimes` + فحص MIME الحقيقي)، وحد أقصى للحجم.
3. نقل جذره من `public_path` إلى `storage/app/public` مع رابط `storage:link` (فصل التخزين عن التنفيذ)، وإضافة `.htaccess` داخل مجلد الرفع: `php_flag engine off` + قاعدة nginx معادلة تمنع تنفيذ PHP.
4. فحص بايتات الملف (magic bytes) لا الامتداد فقط.

### 🔴 C-02 — تخزين الرفع داخل public مع غياب أي حاجز تنفيذ — تكريس RCE ومساحة استضافة

- **الخطورة:** Critical (مرتبطة بـ C-01 — defense-in-depth غائب كلياً)
- **الفئة:** File Upload / Config
- **الملف:السطر:** `config/filesystems.php:50-57` + `public/.htaccess` (لا يحوي أي حماية لـ uploads)

**الوصف:**
حتى المسارات التي تتحقق بقاعدة `image` (listings/events/offers)، تُخزَّن الملفات في `public/uploads` علناً، و`.htaccess` الافتراضي لا يمنع تنفيذ السكربتات داخل المجلدات الفرعية. أي ثغرة مستقبلية في التحقج تترجم فوراً إلى RCE.

**إثبات المفهوم:**
أي ملف يُرفع يصبح متاحاً مباشرة عبر `GET /uploads/<dir>/<hash>.<ext>` — يمكن استضافة صفحة تصيّد تحت نطاق الموقع الموثوق (ضرر حتى بدون RCE).

**الإصلاح:** كما في C-01 (نقطة 3-4)، إضافةً إلى قاعدة خادم تمنع تنفيذ أي شيء غير ثابت داخل مجلد الرفع.

---

### 🔴 C-03 — بيانات دخول مدير ملتزقة في الكود (Seeder)

- **الخطورة:** Critical
- **الفئة:** Credentials / Config
- **الملف:السطر:** `database/seeders/DatabaseSeeder.php:37-52`

**الوصف:**
الـ Seeder ينشئ حساب مدير ببريد قابل للتوقع وكلمة مرور معروفة في المستودع:
- `admin@eventssquare-sa.com` / `Admin@2026`
- `editor@eventssquare-sa.com` / `Editor@2026`

أي نشر يُنفَّذ فيه `db:seed` (وهو جزء شائع من خطوات النشر) يمنح المهاجم حساب مدير جاهزاً. مع غياب throttle على الدخول (H-01) يمكن التأكد من صحة الكلمة بلا عقاب.

**إثبات المفهوم:**
`POST /login` بـ `email=admin@eventssquare-sa.com&password=Admin@2026` → توجيه إلى لوحة التحكم.

**الإصلاح:**
1. قراءة كلمة المرور من متغير بيئة غير ملتزم (`ADMIN_PASSWORD`) مع فشل صريح إن غاب في الإنتاج، أو توليد كلمة عشوائية تُطبع مرة واحدة.
2. حظر تنفيذ الـ Seeder في بيئة production إلا بعلم صريح.
3. تدوير كلمة المرور فوراً في أي بيئة نُفِّذ فيها.

### 🟠 H-01 — غياب الحماية من brute force على تسجيل الدخول

- **الخطورة:** High
- **الفئة:** Authentication
- **الملف:السطر:** `routes/web.php:40` + `app/Http/Controllers/AuthController.php:19-40`

**الوصف:**
لا `throttle` على مسار `POST /login`، لا قفل حساب، لا تأخير متزايد، لا 2FA. `throttle` في `config/auth.php:100` خاص بإعادة تعيين كلمة المرور فقط (غير مستخدم أصلاً).

**إثبات المفهوم:**
سكربت hydra/skript يستطيع إرسال آلاف المحاولات/الدقيقة ضد حساب المدير؛ لا يوجد أي عدّاد أو حجب.

**الإصلاح:** `Route::post('/login', ...)->middleware('throttle:5,1')` كحد أدنى + RateLimiter مخصص بالمستخدم/IP مع قفل تدريجي، وتفعيل 2FA للمديرين (fortify/totp).

---

### 🟠 H-02 — تصعيد صلاحيات: المحرر (editor) يدير المستخدمين والإعدادات

- **الخطورة:** High
- **الفئة:** Authorization / Privilege Escalation
- **الملف:السطر:** `app/Http/Middleware/AdminMiddleware.php:15` + `routes/web.php:55-57` + `app/Http/Controllers/Admin/UserController.php:31-59`

**الوصف:**
الوسيط يسمح بـ `admin` **أو** `editor` لكل مسارات `/admin/*` بما فيها إدارة المستخدمين (تغيير أدوار/حذف) والإعدادات العامة. أي محرر:
1. يستطيع ترقية **أي حساب آخر** إلى admin (قيد "لا تعدّل دورك" يمنع ذاته فقط) — يرقّي حساباً يسيطر عليه ثم يرقّي نفسه.
2. يستطيع **تخفيض المدير الوحيد** إلى دور `user` → اختطاف إداري للمنصة (DoS إداري).
3. يرى بريد/اسم كل المستخدمين (`index`) — تسريب داخلي.

**إثبات المفهوم:**
بجلسة editor: `POST /admin/users/{id} { "role": "admin" }` على حساب شريك → 200 ثم دخول به كمدير كامل.

**الإصلاح:** حصر `users.*` و `settings.*` بـ `role:admin` (وسيط Spatie) أو `->can('manage-users')`؛ منع تعديل/حذف أي حساب يحمل دور admin إلا من قبل admin؛ حماية "آخر مدير" من التخفيض.

### 🟠 H-03 — قاعدة `image` تسمح بـ SVG → XSS مخزَّن

- **الخطورة:** High
- **الفئة:** XSS
- **الملف:السطر:** `app/Http/Controllers/Admin/ListingController.php:106`، `Admin/EventController.php:112`، `Admin/OfferController.php:81` (كل التحقق من `cover_image`)

**الوصف:**
قاعدة `image` في Laravel تقبل `svg` افتراضياً، وSVG يحتمل `<script>` و`onload`. الملفات تُخدَّم من نفس الأصل `/uploads/...` — أي فتح الرابط ينفّذ جافاسكربت بهوية الموقع (سرقة جلسة المدير الذي يطّلع على الرابط).

**إثبات المفهوم:**
ملف `xss.svg` محتواه `<svg xmlns="http://www.w3.org/2000/svg" onload="fetch('/admin/users')...">` يمر تحقق `image` ويُخزَّن؛ فتحه من متصفح المدير ينفّذ السكربت تحت أصل الموقع.

**الإصلاح:** استبدالها بـ `mimes:jpg,jpeg,png,webp` (استثناء svg صراحةً)، أو خدامة SVG عبر معالج ينظّف السكربتات، أو `Content-Security-Policy` + تقديم الرفع من نطاق/مصدر منفصل.

---

### 🟠 H-04 — إعدادات .env خطرة للنشر + مفتاح ملتصق بالمستودع

- **الخطورة:** High (شرط نشر)
- **الفئة:** Configuration / Secret Exposure
- **الملف:السطر:** `.env:3-4` و `.env.example:4`

**الوصف:**
- `.env` الحالي (ونسخته النموذجية) تحمل `APP_DEBUG=true` — نشرها كما هو يعني كشف مسارات، متغيرات بيئة، وأجزاء كود عند أي خطأ.
- `APP_KEY` بقيمة حقيقية ملتزقة في ملف مُتتبَّع ضمن بيئة العمل — إن رُفع مع النشر أو أُدرج في مستودع يُشارك، تُفسَر به كل الجلسات والتوقيعات.
- `LOG_LEVEL=debug` و`MAIL_MAILER=log` (رسائل التواصل ستُدفن في اللوجات).

**إثبات المفهوم:**
أي صفحة خطأ (404 مقصودة تكفي مع debug) تعرض stack trace كاملاً في بيئة إنتاج منسوخة من هذا الملف.

**الإصلاح:** قالب `.env.production` بـ `APP_DEBUG=false` و`APP_ENV=production`؛ توليد `APP_KEY` جديد عند النشر؛ إزالة المفتاح من أي مستودع/نسخة مشتركة؛ `LOG_LEVEL=error` في الإنتاج.

### 🟡 M-01 — نموذج التواصل بلا rate limiting / مضاد سبام

- **الخطورة:** Medium
- **الفئة:** Abuse / Spam
- **الملف:السطر:** `routes/web.php:36` + `app/Http/Controllers/ContactController.php:12-25`

**الوصف:**
لا `throttle` ولا captcha ولا honeypot. التحقق موجود (جيد) لكن يمكن إغراق جدول `contacts` بآلاف الرسائل آلياً — امتلاء قاعدة البيانات + بيانات شخصية زائدة تُهمل (أثر PDPL — راجع §3).

**إثبات المفهوم:** `while(1) curl -d "name=x&subject=y&message=z" /contact` — لا حجب.

**الإصلاح:** `throttle:5,10` على المسار + honeypot + (اختياري) Google reCAPTCHA/hCaptcha، وتنقية المدخلات بمكتبة anti-xss عند العرض في اللوحة.

---

### 🟡 M-02 — كوكي الجلسة غير مؤمَّنة (Secure flag غائب)

- **الخطورة:** Medium
- **الفئة:** Session Management
- **الملف:السطر:** `config/session.php:172` (`'secure' => env('SESSION_SECURE_COOKIE')` — غير معرَّف في .env)

**الوصف:**
بدون `SESSION_SECURE_COOKIE=true` يمكن إرسال كوكي الجلسة عبر HTTP صريح → اعتراض جلسة المدير على شبكة غير موثوقة (MITM). `same_site=lax` و`http_only=true` افتراضياً (جيد)، لكن Secure و`SESSION_ENCRYPT` يُنصح بهما.

**الإصلاح:** في بيئة الإنتاج: `SESSION_SECURE_COOKIE=true` + فرض HTTPS/HSTS على مستوى الخادم.

---

### 🟡 M-03 — غياب رؤوس الأمان (CSP / X-Frame-Options / HSTS)

- **الخطورة:** Medium
- **الفئة:** Headers
- **الملف:السطر:** `bootstrap/app.php:18-27` (لا وسيط رؤوس أمان)

**الوصف:** لا توجد أي رؤوس أمان: النظام قابل للتأطير (clickjacking على أزرار لوحة التحكم)، ولا سياسة محتوى تحدّ من أثر أي XSS مستقبلي.

**الإصلاح:** حزمة مثل `barryvdh/laravel-csp` أو وسيط يدوي يضيف: `X-Frame-Options: DENY`، `Content-Security-Policy` صارمة، `Strict-Transport-Security`، `X-Content-Type-Options: nosniff`، `Referrer-Policy`.

---

### 🟢 L-01 — حقن أحرف البدل في بحث LIKE

- **الخطورة:** Low
- **الفئة:** Injection (غير SQL — parameterized)
- **الملف:السطر:** `app/Http/Controllers/Admin/ListingController.php:23`، `UserController.php:19`، وبقية دوال البحث
- **الوصف:** قيمة البحث تُدمج داخل `LIKE "%{$s}%"` — المستخدم يدخل `%` أو `_` لاستقصاء النطاق. الاستعلام مُعامَل (لا SQLi) لكن يمكن استخراج مقارنات عمياء.
- **الإصلاح:** `addcslashes($s, '%_\\')` قبل الدمج.

### 🟢 L-02 — غياب تسجيل تدقيق للعمليات الحساسة

- **الخطورة:** Low
- **الفئة:** Logging / Accountability
- **الملف:السطر:** عام — لا audit log لأي عملية حذف/تغيير دور/تعديل إعدادات.
- **الإصلاح:** عمود/spatie-activitylog يسجّل من فعل ماذا ومتى — مطلوب أيضاً لمساءلة PDPL.

### 🟢 L-03 — `.env.example` يُشحن `APP_DEBUG=true` كافتراضي

- **الخطورة:** Low | **الفئة:** Config | **الملف:السطر:** `.env.example:4`
- **الإصلاح:** اجعل الافتراضي `false` وفعِّله محلياً فقط.

### نقاط قوة مؤكَّدة (للإنصاف)
- ✅ كل مسارات `/admin/*` محمية فعلاً بـ `auth` + `admin` (`routes/web.php:45`) والوسيط مُسجَّل صحيحاً في `bootstrap/app.php:23-26`.
- ✅ إعادة توليد معرّف الجلسة عند الدخول (`regenerate()`) وإبطال كامل + تدوير التوكن عند الخروج — لا session fixation.
- ✅ Mass Assignment محكوم: كل النماذج تستخدم `#[Fillable]` صراحةً ولا استخدام لـ `unguard()`.
- ✅ لا path traversal في الرفع (أسماء مُجزّأة والوجهة ثابتة بالكود).
- ✅ لا `v-html` في الواجهة — XSS الحقن المباشر عبر Vue مستبعد (يبقى متجه SVG فقط).
- ✅ CSRF مفعَّل افتراضياً (web middleware) وVue يرسل X-XSRF-TOKEN.

## 3) جاهزية PDPL (نظام حماية البيانات الشخصية السعودي)

| المتطلب | الوضع الحالي | الملاحظة |
|---|---|---|
| إشعار/سياسة خصوصية للمعنيين (Art. 5, 9) | ❌ | لا توجد صفحة سياسة خصوصية إطلاقاً (فقط about/contact) — مطلوب نشر إشعار جمع البيانات وغاياتها |
| تحديد غرض وتقليل البيانات (Art. 5) | ⚠️ | نموذج التواصل يجمع هاتف/بريد دون تصريح غرض أو مدة |
| مدة الاحتفاظ والحذف (Art. 6) | ❌ | لا سياسة احتفاظ آلية لجدول contacts — حذف يدوي فقط |
| حقوق المعنيين (وصول/تصحيح/حذف — Art. 7, 18-23) | ❌ | لا مسار لطلب الوصول أو الحذف خارج البريد العام |
| أمان المعالجة (Art. 27) | ❌ | الثغرات C-01..C-03 وH-01..H-02 تجعل مبدأ الأمان غير مستوفى |
| تسريب/انتهاك وإشعار الجهة (Art. 30) | ❌ | لا سجل تدقيق ولا إجراء إشعار خرق موثَّق |
| نقل بيانات خارج المملكة (Art. 44) | ⚠️ | البريد/الاستضافة غير محددين — يجب اختيار استضافة داخل السعودية أو دول بنفس مستوى الحماية |

**الخلاصة:** غير جاهز PDPL حالياً — الحد الأدنى: صفحة سياسة خصوصية بالعربية + سياسة احتفاظ/حذف لcontacts + سجل تدقيق + تأمين الأصول A1/A2/A3.

## 4) الحكم النهائي

### 🚫 ممنوع النشر (NO-GO)

**مانعات النشر الحرجة (يجب إغلاقها قبل أي نشر بلا استثناء):**

1. **C-01 + C-02** — رفع ملفات تعسفية إلى مجلد علني قابل للتنفيذ = RCE كامل على الخادم. استُهلكت جميع شروط الاستغلال: لا تحقق على avatar، تخزين في public، لا حاجز تنفيذ.
2. **C-03** — بيانات مدير ملتزقة في Seeder — إن نُفِّذ db:seed في الإنتاج فالاختراق إداري فوري وموثَّق.

**شروط نشر إلزامية أيضاً (قبل GO):** إغلاق H-01 (throttle دخول)، H-02 (عزل إدارة المستخدمين عن editor)، H-03 (حظر SVG)، H-04 (APP_DEBUG=false + مفتاح جديد + قالب إنتاج)، والحد الأدنى من متطلبات PDPL (سياسة خصوصية + احتفاظ).

**بعد الإغلاقات أعلاه:** البنية العامة سليمة (وسيط الأدوار مفعّل، الجلسات تُدار صحيحاً، Fillable شامل، CSRF مفعّل) — إعادة تدقيق مستهدفة للإصلاحات ثم اختبار اختراق قصير يكفي للتصريح.
